# MediaGrab

Настольное приложение (Electron) для скачивания видео, Shorts, аудио и изображений:
YouTube и Shorts, TikTok, Instagram, VK Видео, SoundCloud, Pinterest. Для каждой ссылки выбирается формат (MP4, WebM, GIF, MP3, M4A, FLAC) и качество.
Интерфейс на русском и английском, светлая и тёмная темы.

Внутри используются [yt-dlp](https://github.com/yt-dlp/yt-dlp), ffmpeg и Deno (JS-движок, который YouTube требует для расшифровки ссылок). Для картинок Pinterest есть собственный загрузчик.

## Запуск

Нужен [Node.js](https://nodejs.org) 20 или новее.

```bash
npm install
npm start
npm test        # необязательно: проверка внутренней логики
```

При первом запуске приложение само скачает yt-dlp и Deno с GitHub (нужен интернет, около минуты). Дальше yt-dlp проверяет обновления раз в два дня.
Если какой-то сайт перестал работать, откройте «Дополнительно» → «Обновить yt-dlp».

## Что делает приложение само

- Если куки браузера не читаются (частая беда Chrome и Edge на Windows), повторяет запрос без них.
- При сбое сети или лимите запросов повторяет загрузку до двух раз (через 5 и 20 секунд), частично скачанное докачивается.
- Если Deno не удалось скачать, использует запасной вариант: сам Electron в режиме Node.
- Берёт вход в аккаунт только для YouTube и только когда сайт его потребовал. Загрузки с аккаунтом стартуют с паузой 5–10 секунд и не чаще 40 в час, чтобы аккаунт не попал под ограничения.
- Если сайт ответил «слишком много запросов» (429), ставит на паузу загрузки с этого сайта (остальные идут): 1 минуту, при повторе 3, затем 5 минут. Если отменить загрузку, ждущую своей очереди для аккаунта, её слот возвращается. Сбой при скачивании субтитров не ломает загрузку видео.
- Если у видео нет качества, выбранного по умолчанию (например 1080p), на карточке пишет, какое максимум доступно.

## Сборка установщика

```bash
npm run dist:win     # Windows: установщик и portable .exe в папке dist/
npm run dist:mac     # macOS (собирать нужно на Mac)
npm run dist:linux   # Linux AppImage
```

Иконка лежит в `build/icon.png` (исходник `build/icon.svg`). electron-builder сам делает из неё `.ico` и `.icns`.

## Выпуск через GitHub Actions

Файл `.github/workflows/build.yml` прогоняет тесты при каждом push, а при теге вида `v1.2.0` собирает установщики под Windows, macOS и Linux и выкладывает их в GitHub Releases:

```bash
git tag v1.2.0 && git push origin v1.2.0
```

Подпись добавляется, если задать секреты репозитория (без них сборка работает, но установщик не подписан, и Windows SmartScreen или macOS Gatekeeper будут предупреждать):

| Секрет | Для чего |
|---|---|
| `WIN_CSC_LINK`, `WIN_CSC_KEY_PASSWORD` | сертификат подписи кода Windows (.pfx в base64) и пароль к нему |
| `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID` | подпись и нотаризация macOS (нужен платный аккаунт Apple Developer) |

В `package.json` замените `YOUR_GITHUB_LOGIN` на свой логин в `build.publish.owner` и в `repository.url`, иначе автообновление не заработает. Разрешения macOS лежат в `build/entitlements.mac.plist`.

## Безопасность

- Загруженные yt-dlp и Deno сверяются с контрольными суммами из релиза на GitHub; при несовпадении файл удаляется и запуск сообщает об ошибке. Если файл сумм получить не удалось, проверка пропускается.
- Сохранённый вход в YouTube шифруется средствами системы (DPAPI в Windows, Keychain в macOS, libsecret в Linux). На время работы создаётся временная расшифрованная копия для yt-dlp в папке данных приложения (`tmp`), обновлённые куки сохраняются обратно после каждой загрузки, при выходе копия удаляется, а остатки после аварийного завершения чистятся при следующем запуске. Если шифрование в системе недоступно, используется обычный файл с правами только для владельца.
- Окно приложения изолировано (sandbox, contextIsolation, строгий CSP). Открытие папок и перетаскивание файлов проверяют путь, а перед запуском системных команд (сон, выключение) есть отсчёт и белый список.

## Автообновление самого MediaGrab

Работает у тех, кто поставил приложение установщиком (portable-версия не обновляется). Приложение раз за запуск проверяет GitHub Releases, скачивает новую версию (проценты видны в жёлтой полосе) и предлагает «Перезапустить и обновить». Проверить вручную можно в «Дополнительно» → «Приложение». Обновление yt-dlp проходит в фоне и не задерживает запуск.

Чтобы это включить:

1. Создайте репозиторий на GitHub и в `package.json` в блоке `build.publish` замените `YOUR_GITHUB_LOGIN` на свой логин (и `repo`, если назвали иначе).
2. Создайте токен GitHub с правом `repo` и задайте его в переменной окружения `GH_TOKEN`.
3. Поднимите `version` в `package.json` и выполните `npm run release`. Сборка загрузится в черновик релиза на GitHub: опубликуйте его.

Пока `publish` не настроен, проверка обновлений тихо пропускается и ничего не ломается.

## Как пользоваться

1. Вставьте ссылку (или несколько, по одной на строку). Можно также перетащить ссылку в окно.
2. Дождитесь, пока появятся превью и доступные качества.
3. Выберите формат и качество. Слева выбираются значения по умолчанию для всех новых ссылок.
4. Нажмите «Скачать» у нужной ссылки или «Скачать всё».

## Дополнительные возможности

- **Плейлисты и каналы.** Вставьте ссылку на плейлист: откроется список видео с галочками, выбранные добавятся в очередь по отдельности.
- **Фрагмент.** У видео в карточке есть раскрывающийся блок «Фрагмент»: двойной ползунок и поля времени (`90`, `1:30` или `1:02:30`), они связаны между собой, рядом показана длина фрагмента. Крайние положения означают весь ролик. Вырезка идёт по ключевым кадрам, поэтому границы могут сдвинуться на пару секунд.
- **Общий прогресс.** Если в очереди несколько ссылок, над списком появляется общая полоса: сколько готово, процент и оставшееся время. Тот же процент виден в заголовке окна и на кнопке в панели задач.
- **Горячие клавиши.** Ctrl+V вставляет ссылку из буфера, Ctrl+Enter добавляет ссылки (или запускает всю очередь, если поле пустое), Ctrl+H открывает историю, Ctrl+L переводит фокус в поле ссылки.
- **Форматы.** MP4 (H.264, воспроизводится везде), WebM (VP9), GIF, MP3, M4A, FLAC. В боковой панели по умолчанию MP4/MP3, остальные выбираются в списке формата на карточке. GIF делается из фрагмента до 30 секунд (ширина 320, 480 или 640 px, 12 кадров/с): задайте начало и конец в блоке «Фрагмент», по умолчанию подставляются первые 10 секунд. M4A берётся без перекодирования, где это возможно, FLAC — без потерь относительно источника (источник сам обычно сжат с потерями).
- **Подписки.** Кнопка «Подписки» над очередью (или «Подписаться на новые» в окне выбора видео): вставьте ссылку на канал или плейлист. Всё, что уже есть, считается просмотренным; пока приложение открыто, раз в час (и через 20 секунд после запуска) проверяются 15 последних видео, новые сразу ставятся на загрузку в выбранном формате. Не больше 30 подписок и 15 новых видео за проверку. Для канала YouTube без вкладки берётся «Видео». Подписки хранятся в приложении и проверяются только при запущенной программе.
- **Трей.** «Дополнительно» → «Не закрывать, а сворачивать в трей»: закрытие окна прячет его в трей, загрузки и подписки продолжаются, процент виден в подсказке значка. Выход — через меню значка.
- **Перетаскивание файлов.** Готовый файл можно перетащить из карточки или из истории прямо в проводник, мессенджер или редактор.
- **Точная вырезка.** Фрагмент по умолчанию режется по ключевым кадрам и может оказаться шире заказанного на несколько секунд. Для GIF границы всегда точные; для видео включается флажком «Точная вырезка фрагмента» (медленнее: фрагмент перекодируется).
- **Прямые эфиры и анонсы** помечаются на карточке и не скачиваются, пока трансляция не закончилась.
- **Очередь не теряется.** Незавершённые карточки (формат, качество, фрагмент) возвращаются после перезапуска, но сами не запускаются. Окно запоминает размер и положение.
- **Управление очередью.** «Отменить все» и «Повторить ошибки» появляются, когда есть что отменять или повторять; число одновременных загрузок (1–4) выбирается в «Дополнительно». В окне выбора видео и в истории есть поиск. Очистка истории и удаление подписки спрашивают подтверждение.
- **Перетаскивание ссылок.** Ссылку или .txt-файл со списком ссылок можно бросить в окно: во время перетаскивания появляется подсказка.
- **Журнал и отчёт.** Ошибки пишутся в `logs/app.log` в папке данных приложения (ротация, пароли прокси и куки маскируются). «Дополнительно» → «Сохранить отчёт об ошибке» сохраняет журнал с версиями в текстовый файл, его удобно приложить к описанию проблемы.
- **Прокси при первом запуске.** Если загрузить yt-dlp не удалось (например, GitHub недоступен), на экране ошибки можно указать прокси и повторить.
- **Качество с подробностями.** В списке качеств видно 60 кадров/с (например, `1080p60`) и примерный размер файла, если сайт его сообщает.
- **Язык звука.** Если у видео несколько звуковых дорожек (оригинал и дубляж), на карточке появляется выбор языка; оригинал помечен. Без выбора берётся дорожка по умолчанию.
- **Субтитры на карточке.** Для MP4 и WebM можно выбрать один язык из реально существующих (ручные и автоматические на языке оригинала), «Без субтитров» или «Как в настройках».
- **Главы.** Если у ролика есть главы, в блоке «Фрагмент» появляется список: выбор главы сразу задаёт начало и конец.
- **Обложка во FLAC.** Вшивается так же, как в MP3 и M4A (флажок «Обложка и теги»).
- **После очереди.** «Дополнительно» → «Приложение» → «После окончания очереди»: закрыть MediaGrab, перевести компьютер в сон или выключить. Перед действием идёт отсчёт (10 или 60 секунд), его можно отменить. Выбор действует только до закрытия приложения, чтобы забытая настройка не выключила компьютер в следующий раз. Незавершённые карточки остаются в очереди и вернутся при следующем запуске.
- **Настройки во вкладках.** Кнопка «Дополнительно» открывает окно с вкладками «Аккаунт и сеть», «Загрузки», «Приложение».
- **Языки.** Русский, английский, украинский, немецкий, испанский (выбор слева внизу).
- **Субтитры.** «Дополнительно» → «Встроить субтитры (MP4)» и языки через запятую, например `ru,en`.
- **Обложка и теги в MP3.** Включено по умолчанию, отключается в «Дополнительно».
- **Имя файла.** «Название», «Автор - Название» или подпапка по сайту.
- **Ограничение скорости.** Чтобы загрузка не занимала весь канал.
- **История.** Кнопка «История» над очередью: открыть файл в папке или скачать снова. Ссылки, которые вы уже скачивали, помечаются «Уже скачивали».
- **Уведомление.** Когда очередь закончилась, а окно приложения свёрнуто, звучит сигнал и показывается уведомление.
- **VK Видео.** Ссылки `vk.com`, `vk.ru`, `vkvideo.ru` (включая клипы) и короткие `vk.cc` распознаются сами. Видео, доступные только вошедшим, друзьям или по особой ссылке, требуют входа: «Дополнительно» → «Аккаунт и сеть» → «Другой способ входа» → Firefox (где вы вошли в VK) или файл cookies.txt. Кнопка «Войти в YouTube» к VK не относится. Если закрытое видео не открылось, на карточке пишется именно это.
- **SoundCloud.** Треки, плейлисты («sets») и страницы артистов: ссылка определяется сама, предлагается MP3, M4A или FLAC (видео там нет), обложка и теги встраиваются. Если трек доступен только по подписке Go+, скачается лишь 30-секундный фрагмент, как и в браузере: это ограничение сайта. Приватные треки по секретной ссылке работают, треки, закрытые для вашего аккаунта, нет.
- **Ссылки из буфера.** Если включить, при возвращении в окно приложение само добавит скопированную ссылку на YouTube, TikTok, Instagram, VK, SoundCloud или Pinterest.

## Вход в YouTube (если он требует подтвердить, что вы не бот)

Проверку «вы не бот» делает сам YouTube, и обойти её навсегда нельзя: она зависит от вашего адреса и аккаунта. Поэтому приложение действует по шагам:

1. Сначала пробует без входа, в том числе другими клиентами YouTube.
2. Если не вышло, на карточке появляется кнопка **«Войти в YouTube»**. Она открывает обычный Chrome или Edge (что найдётся на компьютере) в отдельном профиле. Войдите в аккаунт Google как обычно (лучше отдельным), браузер закроется сам, а куки сохранятся в файл. Вручную ничего копировать не нужно, и шифрование куки в Chrome не мешает. Вход только сохраняется: приложение подставляет его лишь для ссылок, где сайт сам потребовал аккаунт (проверка «не бот», закрытое или возрастное видео). Остальное качается без аккаунта, поэтому риск для него минимален.
3. После входа ссылки, которые упёрлись в проверку, запускаются заново сами. Выйти можно в «Дополнительно» → «Выйти из YouTube».

Если подходящего браузера нет, вход откроется в окне приложения, но Google часто не пускает во встроенные окна. Тогда остаются запасные способы: «Дополнительно» → «Другой способ входа» → Firefox или файл cookies.txt из окна инкогнито. Chrome и Edge в списке нет намеренно: на Windows их защита не даёт прочитать куки.

## Эксперимент: токен подтверждения (PO Token)

Выключен по умолчанию. Включается флажком «Эксперимент: токен подтверждения» в «Дополнительно». Это ещё один способ обойти проверку «вы не бот» на YouTube без входа в аккаунт: YouTube всё чаще требует от клиента специальный токен, и yt-dlp умеет получать его через плагин.

Как это устроено:

1. При включении приложение скачивает с GitHub два небольших компонента проекта [bgutil-ytdlp-pot-provider-rs](https://github.com/jim60105/bgutil-ytdlp-pot-provider-rs): программу `bgutil-pot` (один файл, без Node и Python) и плагин для yt-dlp. Они лежат в папке данных приложения, в подпапке `bin/pot`, и раз в неделю обновляются.
2. Программа запускается на вашем компьютере, слушает только `127.0.0.1` на случайном порту и закрывается вместе с приложением.
3. Плагин подключается через `--plugin-dirs`, а yt-dlp ходит за токеном на этот локальный адрес. Дополнительно используется клиент YouTube `mweb`.
4. Порядок попыток не меняется: сначала скачивание с токеном, затем другие клиенты YouTube, и только потом сохранённый вход.

Если компонентов нет для вашей системы (готовые сборки есть для Windows, macOS и Linux x86_64), скачать их не удалось или сервер не запустился, флажок сам выключается и показывает причину, а приложение работает как обычно. Отключить эксперимент можно в любой момент тем же флажком.

## Если не скачивается

Под любой ошибкой есть строка «Технические подробности»: в ней настоящий текст от yt-dlp и сведения о том, какие куки использовались.

| Симптом | Что сделать |
|---|---|
| YouTube: «подтвердите, что вы не бот» | Кнопка «Войти в YouTube» (см. выше). Если вы за VPN, попробуйте отключить его. |
| Instagram или закрытое видео просит вход | То же самое. Нажмите «Войти» на карточке (вход в окне приложения) или используйте Firefox / cookies.txt. |
| Сайт не открывается из вашей страны | Укажите прокси в «Дополнительно». Прокси применяется к yt-dlp. |
| Всё сломалось после обновления сайта | «Дополнительно» → «Обновить yt-dlp». |

## Заметки

- Качество считается по меньшей стороне кадра, поэтому 1080p у вертикальных Shorts и TikTok означает 1080×1920.
- MP4 собирается с приоритетом H.264 + AAC (воспроизводится везде). Для 1440p и 4K YouTube отдаёт только VP9/AV1: такой MP4 может не открываться в старых плеерах. Для максимальной совместимости выбирайте 1080p.
- Плейлисты не скачиваются целиком: берётся только выбранное видео. Посты Instagram с несколькими файлами скачиваются полностью.
- Качайте только то, на что у вас есть права, и учитывайте правила сайтов.

```

lib/progress.js    разбор прогресса yt-dlp
lib/cookies.js     экспорт кук окна входа в cookies.txt
lib/errors.js      понятные сообщения об ошибках, признаки временных сбоев
lib/messages.js    сообщения главного процесса (ru, en); messages.more.js — uk, de, es
lib/potoken.js     эксперимент: загрузка bgutil-pot и плагина, локальный сервер токенов
lib/gif.js         GIF из ролика через ffmpeg (палитра по ролику)
lib/checksum.js    проверка контрольных сумм загрузок
lib/vault.js       шифрованное хранилище куков входа
```
